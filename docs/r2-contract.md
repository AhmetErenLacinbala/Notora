# R2 integration contract (2026-11-12)
User authorizes R2 storage, 9 GB hard application/cloud gateway cap, upload provenance in protected dashboard, parallel file transfers, and removal of old Solaris/terrain-tiles objects. No paid subscription upgrade. R2 has no assumed native hard cost cap: use a private R2 bucket behind a Cloudflare Workers Free + SQLite Durable Object gateway with independent durable accounting. No public bucket or client S3 credentials/presigned URL bypass. Root verifies account/free-plan/billing and deploys; provider-wide zero cost cannot be promised for pre-existing/other usage.

## Ownership
- Backend agent: apps/server/** only; storage gateway HTTP client, DocumentStore integration, upload admission repair, provenance/dashboard API, server tests.
- Cloud agent: cloudflare/** and tests/unit/r2-gateway.test.ts only; Worker/DO and gateway tests. Root owns dependency manifests/config outside cloudflare.
- Web agent: apps/web/src/** only; parallel network pool independent of render(2), hostId submission, dashboard metadata/storage/deletion and frontend tests. Preserve all PDF canvas and note UX.
- Root: shared/types, docs, package manifests/locks, CI/compose, browser/cloud setup, integration, migration and deployment. No subagent commit/push/deploy or cloud mutations.

## Shared metadata
UploadProvenance = {hostId,ipAddress,countryCode,userAgent}, nullable strings; hostId is client profile ID and is informational only, not authorization. Existing ownerHash remains security authority. Unknown legacy provenance stays null; never invent. ipAddress derived from trusted proxy config, never request JSON; countryCode via local country lookup or validated Cloudflare source, never blindly trust user headers. All provenance only in private metadata/operator dashboard, never public manifest or participants.
DashboardDocumentsResponse.storage optional StorageBudget {provider,usedBytes,reservedBytes,limitBytes,classAUsed,classALimit,classBUsed,classBLimit,month,available}. DashboardDocument adds optional provenance, storageBytes, storagePrefix, storageProvider. DELETE /api/dashboard/documents/:id authenticated + same-origin deletes complete document using store; no active writes/processing deletion races. UI explicit confirmation and conservative errors.
Upload JSON adds optional hostId alongside hostName. Existing uploadPdf/local signature may get optional 4th hostId parameter; owner capability remains unchanged.

## Limits/storage
9 GB means exactly 9_000_000_000 bytes. Counts originals + all page/link/manifest/metadata objects + pending accepted uploads. Backend local scratch has separate existing MAX_STORAGE_MB bound. Repair anonymous uploads: no declared-full reservation before bytes; status/probes do not extend life; genuine progress idle + first-data + absolute deadline; busy stream abort/settle before unlink/release; legacy endpoint same slot/accounting rules.
R2 keys only under notora/<32hex-document-id>/; immutable versioned page paths; original.pdf, metadata.json, manifest.json plus pages/links version folders. Local small records and SQLite stay in volume; successful cloud commit verified before deleting local binary derivatives/original. Existing local records remain readable; provide migration/recovery path rather than blind data deletion. Backend cloud writes parallel <=3, cloud downloads streamed not whole original buffers; current PDF preprocess concurrency1. Worker never rasterizes or parses PDFs.

## Gateway HTTP protocol (final, coordinate changes with root)
All routes use Authorization: Bearer GATEWAY_SECRET, server-only, no query credentials. JSON errors {error:string}, quota/storage unavailable fail closed. Gateway maximum individual request body 8 MiB; larger objects via multipart. Object keys strictly notora/<32hex>/... with safe segments only.
- GET /v1/status -> {usedBytes,reservedBytes,limitBytes,classAUsed,classALimit,classBUsed,classBLimit,month}; hard max9e9, default Class A cap800000/month, Class B cap8000000/month (UTC). Charge before every R2 op including maintenance/retries; never allow reset/deploy bypass. Limits may only configure down. Additionally persist daily UTC caps A=20_000 and B=200_000; billing cycle is not a calendar month, so calendar-month caps alone are insufficient. Charge both daily and monthly counters atomically before every R2 operation. Status can expose classADailyUsed/classADailyLimit/classBDailyUsed/classBDailyLimit.
- PUT /v1/objects/<key> Content-Length + Content-Type, max8MiB -> {key,size,etag}. Keys immutable: existing identical retry may report existing; do not overwrite mismatched bytes. Account in-flight bytes before R2 op, pending crash stays charged until cleanup verified.
- GET /v1/objects/<key> -> streaming body + content-type/content-length/etag, no-store. HEAD same headers. DELETE ->204; release only after successful delete. Missing object idempotent delete allowed; immutable metadata updates need explicit DELETE then PUT or versioned key.
- POST /v1/multipart JSON {key,size,contentType} -> {uploadId}. Authenticated backend stat-known actual files only; reserve declared size plus transient parts safely. Max parts/request8MiB; backend uses 8MiB parts, last can be smaller.
- PUT /v1/multipart/<uploadId>/parts/<partNumber> -> {partNumber,etag}; bounded lengths, duplicate retry handling, validate total<=declared.
- POST /v1/multipart/<uploadId>/complete JSON {} -> {key,size,etag}; validate contiguous parts and exact total; store result for idempotent retry.
- DELETE /v1/multipart/<uploadId> ->204; abort then release; error retains charge.
- GET /v1/pending?prefix=<notora/id/>&cursor=<cursor> -> {pending:[{key,uploadId?:string}],truncated,cursor?}. Authenticated SQLite-ledger listing only; includes committed and pending entries so interrupted writes/deletes can be reconciled. No R2 operation. Abort listed unfinished multipart uploads or DELETE other keys before listing/deleting remaining R2 objects.
- GET /v1/objects?prefix=<notora/id/...>&cursor=<cursor> -> {objects:[{key,size}],truncated,cursor?}; paginated R2 list billed Class A. Used for migration/reconciliation/delete, never list per ordinary page fetch.
Worker binding BUCKET and singleton SQLite DO QUOTA. Exact env backend: R2_GATEWAY_URL, R2_GATEWAY_SECRET; cloud GATEWAY_SECRET; bucket notora-documents. No automatic paid upgrade. Backend independent durable operation caps and cloud9GB check before writes; cloud gateway is authoritative gate.
