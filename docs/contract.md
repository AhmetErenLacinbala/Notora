# Notora implementation contract (v1)

## Scope and deployment
One TypeScript monorepo, one long-running Node/Fastify process in one Docker container, existing VPS Traefik provides HTTPS. Root owns deploy/config; no subagent deploys. English minimal UI. Original PDF and derived pages live under DATA_DIR (persistent volume). Notes are NEVER stored on server disk; shared editing is ephemeral while clients are connected. Creator-owned history is only in browser storage, independent of display name and guest caches.

## HTTP
- POST `/api/documents`: multipart field `file` (PDF, max default 256 MiB), streaming to disk. Returns 202 UploadResult after durable upload; preprocessing runs with concurrency 1. Generate cryptographically random document id, access token, owner token; persist only token hashes alongside document metadata. Request title comes from sanitized filename. Validate PDF, enforce total storage budget, no shell interpolation.
- GET `/api/documents/:id`: DocumentManifest. Processing returns empty page/outline arrays until ready; UI polls. Invalid capability: 401/404 without document disclosure.
- GET `/api/documents/:id/pages/:number.pdf`: standalone single-page PDF for ORIGINAL 1-based page number; immutable version in manifest. Must validate auth. Serve binary efficiently, private browser cache, ETag. Backend may also accept `?v=<version>` for cache keys.
- GET `/api/documents/:id/pages/:number/links`: PageLink[] in displayed canonical top-left coordinates. Internal destinations retain original page numbers. External URLs only http(s)/mailto, never javascript.
- HTTP document requests use `Authorization: Bearer <accessToken>` (not query tokens).
- GET `/healthz`: nonsecret JSON status/revision.
- SPA routes `/` and `/r/:documentId`; capability in URL fragment `#<accessToken>`, not the request path. Owner token is local only. Static build directory dist/web. WebSocket `/ws`.
- Import qpdf for page extraction and Python pypdf for manifest/outline/link extraction. Dimensions apply CropBox, Rotate and UserUnit. Preserve originals, never rasterize full book. No note chunks/files on backend.

## Client data module (data agent owns apps/web/src/lib)
`storage.ts` exports async `getProfile(): Promise<Profile|null>`, `saveProfile(Profile)`, `listOwnedProjects(): Promise<OwnedProject[]>`, `saveOwnedProject(OwnedProject)`, `getOwnedProject(id): Promise<OwnedProject|undefined>`, `loadCamera(id): Promise<Camera|undefined>`, `saveCamera(id, Camera)`.
`api.ts` exports `uploadPdf(file: File, onProgress?: (percent:number)=>void): Promise<UploadResult>`, `getManifest(id,token): Promise<DocumentManifest>`, `getPageBytes(id,version,page,token,signal?): Promise<Uint8Array>`, `getPageLinks(id,page,token,signal?): Promise<PageLink[]>`. PDF page cache key includes id/version/page. Read only requested cached pages; abort obsolete requests; do not load all cache into RAM. Guest cache NEVER adds history. Upload use XHR for progress, do not base64 file.
`workspace.ts` exports class `WorkspaceSession` implementing shared WorkspaceSessionApi. Stable getSnapshot object until changes; UI uses useSyncExternalStore. Construction no network; connect initializes. Cursor coordinates are shared unzoomed STAGE coordinates. setVisibleRange requests only relevant text bodies, including notes anchored before the visible page but extending into it. All index metadata is small and loaded once; bodies lazy. createNote returns id immediately; selected note must stay loaded while being edited. UI calls setEditingNote(id) on focus and setEditingNote(null) on blur so an offscreen focused note remains subscribed.

## Note model and synchronization
Yjs root `index` document holds `getMap<NoteMeta>('notes')`; one independently loadable Y.Doc per note key `note:<id>` holds `getText('text')`. These are IndexedDB records, not region files. No stored width/height, no rich text or shapes. Meta lineCount is derived from literal newlines, with font size 18 and line height 26. Text is never automatically wrapped. Source note body persists as Yjs binary updates (not reconstructed JSON).
Wire uses shared ClientMessage/ServerMessage. Updates are base64 Yjs binary (text only). First frame join; server validates both access and optional owner token, assigns color based on clientId. index always subscribed. subscribe replaces note-key subscriptions. Server merges Yjs updates in ephemeral RAM and routes index to all, note bodies to subscribers AND owner (even offscreen); no content log or disk write. On a missing state ask owner/peers via need-state; clients respond from RAM or requested IDB record with state. On welcome client sends saved/in-memory index; server sends current index and requested note state. Merge before broadcast; avoid echo loops. Room memory released after final disconnect. Validate sizes, keys, finite cursor values and max text to avoid unbounded frames.
Receiving an offscreen update queues binary persistence without rendering/loading every note. Local state loads lazily and merges with remote updates (never overwrites). Reconnect resends index + unsent/loaded note state so edits made during disconnect converge.
UI/RAM and WS updates are immediate. IndexedDB commits wait SAVE_IDLE_MS=10000 after input activity; activity() resets the timer only when dirty. UI calls activity on pointer/keyboard input. Incoming content updates also mark dirty and schedule save; cursors do not dirty documents. No default y-indexeddb adapter (it writes immediately). Flush on controlled close/visibility hidden, truthful pending/saving/saved/error status, no guarantee on OS crash. Never discard dirty state before successful save.

## UI ownership and integration
UI agent owns App.tsx, components/**, styles.css. Root owns main.tsx, index.html, vite config. Import shared from relative packages path (no aliases). Route without extra router library. First visit asks only name. Home: Notora wordmark, PDF open control, creator-only recent list. Upload progress/processing, useful errors. Workspace: tiny top bar with home/title, outline toggle, zoom controls, share button, participants and local save state. Main surface virtualized PDF pages with wide margins; double-click empty area adds plain text. Text editing uses DOM/textarea, preserves newlines, no fixed persisted dimensions, safe text rendering. Basic text deletion allowed; no drawing/shape/rich-text toolbar. Text overlay is independent of page DOM so spilling notes survive page virtualization. Render PDF text layer for selection and imported link rectangles for navigation; original outline uses original destinations. Participant click jumps to latest cursor, never continuous forced camera following. Cursor shown with name. Camera restored locally. PDF load/render abort+cleanup on unmount; bounded worker/render concurrency, no 300-worker allocation. Note keys use only note id; empty newly created notes can be removed on blur.

## Verification
Test cross-page note visibility, creator-vs-guest history, 10-second save timing, reconnect merging, offscreen guest edits reaching owner, capability auth, PDF extraction dimensions/navigation and page isolation. Root handles real browser two-client tests, virtualized network/RAM checks, Docker and live deployment. Request changes to shared interfaces by message before modifying.
