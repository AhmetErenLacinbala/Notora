# Notora implementation contract (v1)

The later [drawing and local-first contract](drawing-local-contract.md) supersedes upload-on-open and no-drawing restrictions below. Existing text/camera formats remain compatible.

## Admin and guest persistence update
The original PDF creator/sharer is the admin, authenticated by the existing owner capability. Display names, connection order, and client-provided participant IDs never confer admin privileges. Only the server-confirmed admin can remove a non-admin peer in the same room. A kick removes the current session and prevents automatic reconnection; this is not a permanent identity ban. Rejected/removed peers cannot continue sending updates while their sockets close. Active duplicate participant IDs must not displace another peer.

Only local creators and authenticated owners retain PDF cache, camera, and Yjs data in IndexedDB. Guests keep document data in session RAM and never read/write document records in IndexedDB; their small display-name profile remains allowed. Guest lazy body unloading/reloading and reconnect must preserve unsent changes in RAM and continue forwarding edits to the owner for delayed local persistence. Guest status says Session only. HTTP page and link responses use private, no-store; owners use their explicit IndexedDB page cache. Safely remove legacy guest page caches/cameras when opening that document, guarded against owned records. Do not purge existing legacy annotation records, which may contain a sole copy of an edit.

## Private dashboard update
The user explicitly authorized `/dashboard` as a separate operator panel; this supersedes the earlier no-dashboard restriction only for this scope. English minimal UI lists uploaded file names, their creator/host names, upload date/time and last access date/time. No account management, file deletion, download links, analytics or guest history is added. Dashboard bypasses the public display-name prompt and browser document storage. Existing PDF metadata remains readable; unknown historic host/access data is null and shown as Not recorded.

The root-owned shared types are DashboardDocument, DashboardDocumentsResponse and DashboardSession. API endpoints are POST `/api/dashboard/login` (JSON username/password), GET `/api/dashboard/session`, POST `/api/dashboard/logout`, GET `/api/dashboard/documents?offset=0&limit=50`. All document-list data requires a valid operator session; responses are private/no-store and never include access/owner capabilities or hashes. Login uses server-only DASHBOARD_USERNAME and DASHBOARD_PASSWORD_HASH (scrypt:<32 hex salt>:<128 hex digest>, Node crypto default scrypt parameters, 64-byte key), fails closed when unconfigured, and creates a random expiring HttpOnly SameSite=Strict cookie (Secure in production). Logout revokes it. State-changing routes enforce same origin and login attempts are bounded. Never commit real credentials.

Node's built-in SQLite stores small dashboard metadata in DATA_DIR/dashboard.sqlite3 within the existing data volume; PDF originals/manifests are retained and notes/drawings remain outside server persistence. Each file has one host/last-access record rather than an unbounded event log. New upload-session JSON accepts optional hostName; uploadPdf/uploadLocalDocument receive it as an optional third argument and App passes the current profile name. It is bound to that new upload only. Verified owner joins can refresh the host name, guests cannot. Successful document reads and admitted WebSocket joins update last access; unauthorized requests and dashboard reads do not. Old timestamps must not be fabricated. Root owns shared/types, data upload plumbing, compose/env/docs, integration and publishing; server and UI agents own their respective directories.

## Scope and deployment
One TypeScript monorepo, one long-running Node/Fastify process in one Docker container, existing VPS Traefik provides HTTPS. Root owns deploy/config; no subagent deploys. English minimal UI. Original PDF and derived pages live under DATA_DIR (persistent volume). Notes are NEVER stored on server disk; shared editing is ephemeral while clients are connected. Creator-owned history is only in browser storage, independent of display name and guest caches.

## HTTP
- POST `/api/documents`: multipart field `file` (PDF, max default 256 MiB), streaming to disk. Returns 202 UploadResult after durable upload; preprocessing runs with concurrency 1. Generate cryptographically random document id, access token, owner token; persist only token hashes alongside document metadata. Request title comes from sanitized filename. Validate PDF, enforce total storage budget, no shell interpolation.
- GET `/api/documents/:id`: DocumentManifest. Processing returns empty page/outline arrays until ready; UI polls. Invalid capability: 401/404 without document disclosure.
- GET `/api/documents/:id/pages/:number.pdf`: standalone single-page PDF for ORIGINAL 1-based page number; immutable version in manifest. Must validate auth. Serve binary efficiently, private browser cache, ETag. Backend may also accept `?v=<version>` for cache keys.
- GET `/api/documents/:id/pages/:number/links`: PageLink[] in displayed canonical top-left coordinates. Internal destinations retain original page numbers. External URLs only http(s)/mailto, never javascript.
- HTTP document requests use `Authorization: Bearer <accessToken>` (not query tokens).
- GET `/healthz`: nonsecret JSON status/revision.
- SPA routes `/` and `/r/:documentId`; capability in URL fragment `#<accessToken>`, not the request path. Owner token is local only. Static build directory dist/web. WebSocket `/ws`.
- Import qpdf for page extraction and Python pypdf for manifest/outline/link extraction. Dimensions apply CropBox, Rotate and UserUnit. Preserve originals, never rasterize full book. No note chunks/files on backend.

## Client data module (data agent owns apps/web/src/lib)
`storage.ts` exports async `getProfile(): Promise<Profile|null>`, `saveProfile(Profile)`, `listOwnedProjects(): Promise<OwnedProject[]>`, `saveOwnedProject(OwnedProject)`, `getOwnedProject(id): Promise<OwnedProject|undefined>`, `loadCamera(id): Promise<Camera|undefined>`, `saveCamera(id, Camera)`.
`api.ts` exports `uploadPdf(file: File, onProgress?: (percent:number)=>void): Promise<UploadResult>`, `getManifest(id,token): Promise<DocumentManifest>`, `getPageBytes(id,version,page,token,signal?): Promise<Uint8Array>`, `getPageLinks(id,page,token,signal?): Promise<PageLink[]>`. PDF page cache key includes id/version/page. Read only requested cached pages; abort obsolete requests; do not load all cache into RAM. Guest cache NEVER adds history. Upload use XHR for progress, do not base64 file.
`workspace.ts` exports class `WorkspaceSession` implementing shared WorkspaceSessionApi. Stable getSnapshot object until changes; UI uses useSyncExternalStore. Construction no network; connect initializes. Cursor coordinates are shared unzoomed STAGE coordinates. setVisibleRange requests only relevant text bodies, including notes anchored before the visible page but extending into it. All index metadata is small and loaded once; bodies lazy. createNote returns id immediately; selected note must stay loaded while being edited. UI calls setEditingNote(id) on focus and setEditingNote(null) on blur so an offscreen focused note remains subscribed.

## Note model and synchronization
Yjs root `index` document holds `getMap<NoteMeta>('notes')`; one independently loadable Y.Doc per note key `note:<id>` holds `getText('text')`. These are IndexedDB records, not region files. No stored width/height, no rich text or shapes. Meta lineCount is derived from literal newlines. Font size defaults to 18; derived line height scales from 26 at the default font size. Text is never automatically wrapped. Source note body persists as Yjs binary updates (not reconstructed JSON).
Wire uses shared ClientMessage/ServerMessage. Updates are base64 Yjs binary (text only). First frame join; server validates both access and optional owner token, assigns color based on clientId. index always subscribed. subscribe replaces note-key subscriptions. Server merges Yjs updates in ephemeral RAM and routes index to all, note bodies to subscribers AND owner (even offscreen); no content log or disk write. On a missing state ask owner/peers via need-state; clients respond from RAM or requested IDB record with state. On welcome client sends saved/in-memory index; server sends current index and requested note state. Merge before broadcast; avoid echo loops. Room memory released after final disconnect. Validate sizes, keys, finite cursor values and max text to avoid unbounded frames.
Receiving an offscreen update queues binary persistence without rendering/loading every note. Local state loads lazily and merges with remote updates (never overwrites). Reconnect resends index + unsent/loaded note state so edits made during disconnect converge.
UI/RAM and WS updates are immediate. IndexedDB commits wait SAVE_IDLE_MS=10000 after input activity; activity() resets the timer only when dirty. UI calls activity on pointer/keyboard input. Incoming content updates also mark dirty and schedule save; cursors do not dirty documents. No default y-indexeddb adapter (it writes immediately). Flush on controlled close/visibility hidden, truthful pending/saving/saved/error status, no guarantee on OS crash. Never discard dirty state before successful save.

UI agent owns App.tsx, components/**, styles.css. Root owns main.tsx, index.html, vite config. Import shared from relative packages path (no aliases). Route without extra router library. First visit asks only name. Home: Notora wordmark, PDF open control, creator-only recent list. Upload progress/processing, useful errors. Workspace: tiny top bar with home/title, outline toggle, zoom controls, share button, participants and local save state. Main surface virtualized PDF pages with wide margins; double-click empty area adds plain text. Text editing uses DOM/textarea, preserves newlines, no fixed persisted dimensions, safe text rendering. Basic text deletion allowed; no drawing/shape/rich-text toolbar. Text overlay is independent of page DOM so spilling notes survive page virtualization. Render PDF text layer for selection and imported link rectangles for navigation; original outline uses original destinations. Participant click jumps to latest cursor, never continuous forced camera following. Cursor shown with name. Camera restored locally. PDF load/render abort+cleanup on unmount; bounded worker/render concurrency, no 300-worker allocation. Note keys use only note id; empty newly created notes can be removed on blur.

## Note box interaction update
User explicitly authorized pale pink note fill at alpha 0.10 and stroke at alpha 0.20, multiple selection and deletion, two font-size buttons at the selected box's top-left, and border dragging. Do not add other formatting tools.
`NoteMeta.fontSize` is optional for backward compatibility (default 18). Use shared `noteFontSize`, `noteLineHeight`, `noteHeight`, `NOTE_PADDING`, and `NOTE_BORDER`; width/height remain derived only. Font size range 1–72, step 2 (clamped at the limits). Existing IndexedDB/Yjs records remain readable with no destructive migration.
Workspace UI keeps a separate next-note font size state, initially 18. A local font-size button change updates both the selected note and this state; selection and incoming peer updates do not change the default. `createNote(anchorPage, x, y, fontSize?)` accepts the initial font size (default 18) and writes it with the initial note metadata, so new notes use the last locally chosen size immediately. This preference is workspace state, not an additional persisted setting.
`WorkspaceSession.updateNote(id, patch)` accepts only finite x/y and a bounded fontSize, preserves existing text/metadata, and follows the existing live-sync/local-save behavior. `deleteNotes(ids)` removes selected index entries in one Yjs transaction; `deleteNote` stays compatible. Drag coordinates are canonical units (pointer delta divided by zoom); anchorPage stays unchanged so notes can cross pages. Empty-area dragging selects intersecting note boxes without a modifier key; Delete/Backspace removes selection only outside editable text inputs. Normal typing/deleting inside text must remain native text editing. Border dragging uses pointer capture and releases it on cancel/up; content remains editable. Selection is local UI state. A selected box shows only its font decrease/increase buttons, with accessible labels. Preserve page text selection, local delayed saves, shared editing, and lazy initial note/page loading.

## Upload transport update
The shared production proxy has a 60-second request-body deadline (reproduced as HTTP 502 at 60.62s). Do not alter shared Traefik configuration. Notora uses small independent HTTP uploads while storing ONE sequential `.part` file; this does not introduce persistent chunk files or concatenate full PDFs in browser memory.
- POST `/api/uploads`, JSON `{filename,size}` -> 201 `UploadSession {uploadId,uploadToken,offset:0}`. Validate nonempty size <= MAX_UPLOAD_MB, bounded active sessions (8), and total storage budget. Cryptographic separate upload capability.
- GET `/api/uploads/:id`, bearer uploadToken -> 200 `UploadStatus {offset,size}`.
- PUT `/api/uploads/:id`, bearer uploadToken, `Upload-Offset` header, `Content-Type: application/octet-stream` -> 200 `{offset}`. Maximum body 1 MiB. Stream append in one file. Offset mismatch/overlap -> 409 `{error,offset}`. Reject overruns; on failed/aborted chunk truncate back to committed offset and roll back byte accounting. Commit only after complete chunk.
- POST `/api/uploads/:id/complete`, bearer uploadToken -> 202 `UploadResult`. Exact size, PDF header, durable original and metadata before returning; qpdf validation/extraction is queued and manifests report processing/error. Completion retry returns same result for the session lifetime if a response was lost; raw result tokens stay RAM-only, normal document record stores hashes.
- Sessions expire after 30 idle minutes; remove partial bytes and release their budget. Restarts may discard incomplete uploads; do not expose tokens or names in logs. Existing POST `/api/documents` remains compatible but browser uses chunk transport.
- Client `uploadPdf` signature remains unchanged. Use File.slice + XHR per chunk, sequential, no entire-file buffer. Start64KiB, adapt toward ~10s/chunk bounded16KiB..1MiB; retry transient failed requests a bounded number of times, query offset before retry to avoid duplicates, reduce chunk size on timeout/502. Progress stays monotonic and below100 until complete. Keep API/cache behavior outside upload unchanged.

## Canvas interaction and desktop retention update
Latest user request supersedes modifier-based multi-selection and desktop offscreen eviction. No new toolbar/tool modes. Drag empty workspace area to draw a selection rectangle; select intersecting loaded note boxes and allow existing group border-drag/delete. Preserve text selection/editing and PDF links; empty click clears selection, double-click still creates a note. Selection coordinates use canonical stage units. Selection must not trigger note creation on release after a drag.
The viewport is a fixed clipped canvas, not a giant native horizontal scroll area. Keep existing canonical pageLayout/note/cursor coordinates and Camera fields: scrollLeft/scrollTop denote pixel camera offsets even when no native scrolling is used. Camera can pan beyond content edges. CSS transform is translate(-scrollLeft,-scrollTop) scale(zoom). Wheel/trackpad pans two axes; Command or Ctrl + wheel zooms smoothly at the pointer (prevent browser page zoom via a non-passive native wheel listener). Existing +/- buttons zoom at viewport center. Middle-button drag may pan without adding UI. Default camera centers the first page with usable side margins; persisted cameras restore. Outline, participant jump, note placement/drag, visible range, camera persistence and resize must all use the same camera transform.
Desktop detection is matchMedia('(hover: hover) and (pointer: fine)'); touch/mobile retains offscreen virtualization. Initially fetch only nearby pages. Once desktop page rendering completes, retain that page component and its canvas/text/links for the open workspace, without eviction on scroll. Clear on workspace/document/version change. Unvisited/offscreen pending pages remain lazy; retain render concurrency 2 and release PDF.js workers after rendering. Do not eagerly fetch all pages. During zoom preserve the last good canvas until replacement is ready; only nearby pages refresh raster resolution after the zoom settles.
Integration props for PdfPage: existing fields plus active:boolean (nearby, eligible for rendering), retain:boolean (desktop), onReady:(pageNumber:number)=>void. Workspace renders nearby union completed desktop pages, keys by version/page (never zoom). PdfPage owns retention-safe render behavior; Workspace owns retained-page set and camera/selection UI. Root owns apps/web/src/lib/canvasGeometry.ts helpers and its tests; UI agent may import those helpers. No shared persisted schema or backend changes are needed.
